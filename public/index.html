clipsync needs a secure connection

Browsers only expose the Web Crypto API — the thing that encrypts every item before it leaves this device — on HTTPS pages, or on localhost. This page was loaded over plain HTTP from , so clipsync cannot encrypt anything and has stopped rather than send your clipboard in the clear.

Two ways to fix it:

  • Put clipsync behind a reverse proxy with a TLS certificate and reach it over https://. This is the right answer for a shared or internet-facing instance.
  • Or open it as http://localhost:4173 on the machine that runs it, which browsers treat as secure.

Full instructions are in the project README under “Self-hosting”.
